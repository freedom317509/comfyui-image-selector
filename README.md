# TraceLab Image Selector

给 ComfyUI 用的 **Best-of-N 图像优选节点**：一次生成 N 张，自动挑出其中最重要的 K 张，把「抽卡」变成「筛选」。

批量采样时最浪费时间的一步不是生成，是**在一堆图里挑**。这个节点用三个可解释的画质指标给每张图打分，只把高分图传到下游（放大、保存、送去重绘），并输出一份可读报告。

## 它做什么

```
KSampler (batch_size=8) ──► Best-of-N 图像优选 ──► SaveImage
                                    │
                                    └──► report（文本报告，每张图的分数明细）
```

节点参数：

| 参数 | 说明 |
|---|---|
| `images` | 待筛选的图像批 |
| `top_k` | 保留几张；超过批量大小时自动收敛 |
| `w_sharpness` | 锐度权重，默认 0.50 |
| `w_contrast` | 对比度权重，默认 0.25 |
| `w_colorfulness` | 色彩丰富度权重，默认 0.25 |

输出两个端口：`selected`（筛完的 IMAGE 批，顺序与原始索引一致）和 `report`（纯文本，可直接接 Show Text）。

## 三个指标怎么算

| 指标 | 算法 | 为什么这么选 |
|---|---|---|
| 锐度 | 逐通道 4 邻域拉普拉斯响应的方差，再取通道平均 | 拉普拉斯方差是业界最常用的无参考清晰度指标，算得快，且不需要额外模型 |
| 对比度 | 逐通道像素标准差，再取通道平均 | 衡量明暗层次，能压掉「灰蒙蒙」的图 |
| 色彩丰富度 | Hasler & Süsstrunk (2003) 色彩丰富度度量 | 同时考虑色彩变化量与平均色偏，比单纯统计 HSV 饱和度更接近人眼感受 |

三个指标量纲差异极大（锐度动辄上千，对比度不到 1），所以**先在批内做 min-max 归一化再加权求和**，否则总分会被锐度完全支配。当一批图某项指标全相同时，归一化退化为 0.5 的中性分，不会因为除零炸掉。

## 安装

**方式一：手动放目录（推荐，方便改代码）**

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/freedom317509/comfyui-image-selector.git
# 或者直接把本文件夹整个复制进去
```

重启 ComfyUI，在节点面板搜索 `Best-of-N`，位于 `tracelab/select` 分类下。

**方式二：ComfyUI-Manager**

把本文件夹压缩后通过 Manager 的 `Install Custom Nodes → Install from file` 加载。

> 接口兼容性：新版 ComfyUI 走 V3（`comfy_api.latest`）；老版本没有 `comfy_api` 时，`__init__.py` 会自动回退到 V1 的 `NODE_CLASS_MAPPINGS` 注册方式，启动日志里会打印一行提示。

## 跑测试

核心打分逻辑是纯 numpy 的，可以脱离 ComfyUI 单独验证：

```bash
# 用 ComfyUI 便携版自带的解释器
python_embeded\python.exe test_core.py
```

会用合成图（纯色块 / 平滑渐变 / 黑白棋盘 / 高饱和棋盘）检验排序是否符合直觉，并包含一个回归用例。

## 一个真实踩过的坑

v0.1 的锐度是先把图转成 Rec.601 亮度图再算拉普拉斯方差。测试时发现：一张红蓝高饱和图被判成「模糊」。

原因很直接——红色 (0.95, 0.15, 0.10) 和蓝色 (0.05, 0.35, 0.95) 的亮度分别是 0.38 和 0.33，差值不到 0.05。转成灰度后两块几乎同色，**色度边缘直接消失**，拉普拉斯响应接近 0。

修法：改成逐通道算拉普拉斯方差再取平均，色度边缘就能被正确识别。测试里为此加了一条回归用例，固定住「红蓝拼接图必须被判定为锐利」这个行为。
